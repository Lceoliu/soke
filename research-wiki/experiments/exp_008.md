## Motivation

R025 diagnosed the root cause of mT5 failure (G11):

- **mT5 oracle BLEU4 = 1.890** (NN retrieval in encode_continuous() space) ≈ mT5 baseline = 1.742
- **Mean NN cosine = 0.87** across different sign sentences in the CSL-Daily test set
- R026 data scale curve confirms: even at 18k samples mT5 is near its ceiling

**Conclusion**: The VAE encoder produces "acoustic class" embeddings — trained purely for reconstruction, different sign sentences map to nearly the same region of cosine space. mT5 cannot distinguish them. The fix is not more data or a better LM; it is a better encoder.

## Research Question

Can fine-tuning the VAE encoder with a contrastive sign↔text objective (while keeping decoder + quantizer frozen) reduce the inter-sentence cosine similarity enough to raise mT5 downstream BLEU4 from ~1.7 to ≥ 3.0?

## Method (Plan A)

### Frozen vs. Trainable Parameters

| Component | State | Reason |
|---|---|---|
| VAE encoder (all 3 VAEs) | **Trainable** | This is what we want to improve |
| VAE quantize_in (all 3 VAEs) | **Trainable** | Projects encoder output to code_dim — changes with encoder |
| VAE quantizer (LFQ) | **Frozen** | Codebook should remain consistent; semantic info already flows through encoder |
| VAE quantize_out | **Frozen** | Only needed for reconstruction path, not contrastive |
| VAE decoder | **Frozen** | Reconstruction quality (claim:C1) should not regress |

### Loss Function

```
L = λ_recon × SmoothL1(decode(quantize(encode(pose))), pose)
  + λ_contra × InfoNCE(mean_pool(encode_continuous(pose)), mT5_encode(text))
```

- `λ_recon = 1.0` — keeps reconstruction quality from collapsing
- `λ_contra = 0.5` — injects semantic discrimination signal (ablate: 0.1, 1.0)
- InfoNCE: symmetric, in-batch negatives, temperature τ=0.07 (learnable)
- `encode_continuous()` = encoder(preprocess(x)) → quantize_in(x) → postprocess(x): continuous latent before quantization
- Reconstruction loss applied to full forward pass (encoder → quantize_in → LFQ → quantize_out → decoder)

### Training Details

- **Starting point**: Pre-trained Conv1d VAE (same as R006/R025)
- **Optimizer**: AdamW, lr=3e-5 (lower than original to avoid destroying encoder), weight_decay=1e-4
- **Scheduler**: CosineAnnealingLR, T_max=50 epochs, η_min=1e-6
- **Batch size**: 128 sign-text pairs
- **Text encoder**: Frozen mT5 encoder (same as in train_contrastive_pretrain.py)
- **Epochs**: 50 (check convergence via oracle BLEU4 tracked at val time)
- **Dataset**: CSL-Daily train split only

### Validation

Every 5 epochs: run R025-style oracle evaluation on val set:
- oracle BLEU4 (NN retrieval in new encode_continuous space)
- mean NN cosine

### Success Gate (before R028)

- oracle BLEU4 > 3.0 on val set
- mean NN cosine < 0.78 on val set

If these are not met after 50 epochs → try λ_contra=1.0 for 20 more epochs → if still fails → Plan B (masked sign prediction).

## Script

`scripts/train_semantic_vae_finetune.py`

Key differences from `train_contrastive_pretrain.py`:
- VAE encoder + quantize_in are trainable (not fully frozen)
- Reconstruction loss is computed via full forward pass
- Gradient flows through encoder from both recon loss AND contrastive loss
- After training: save fine-tuned VAE encoder weights (not just projection)
- Validation loop computes oracle BLEU4 in-situ

## Risk Analysis

| Risk | Probability | Mitigation |
|---|---|---|
| Reconstruction loss spikes (decoder sees different encoder) | Medium | Keep λ_recon=1.0; monitor recon loss; use low lr=3e-5 |
| Contrastive loss decreases but oracle BLEU4 doesn't improve | Medium | Mean-pool may lose temporal info; try per-frame contrastive variant |
| Overfitting to training set (small dataset, 18k) | Medium | Early stopping on val oracle BLEU4; weight decay=1e-4 |
| Encoder collapses (all embeddings map to same point) | Low | SmoothL1 recon loss prevents full collapse; monitor grad norms |
