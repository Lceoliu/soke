## What We Think Happened

### Hypothesis H1: Sequence-Level Alignment ≠ Token-Level Decodability (HIGH CONFIDENCE)

Our contrastive pre-training aligned **mean-pooled** sign embeddings to **mean-pooled** text embeddings via InfoNCE (batch size 512, temp ~0.06). The sign projection learned to represent a whole sentence as a point in text space (acc_s2t=27.7%).

But the mT5 decoder must generate one token at a time, conditioned on the **full temporal sequence** of sign embeddings. Each frame-level embedding in the sequence must carry sufficient signal for the decoder to pick the next word. Mean-pool alignment does NOT teach the individual time steps to be decodable — it only teaches a global summary to be retrievable.

Evidence: SignCL (Ye et al. 2024, NeurIPS) specifically addresses this: "gloss-free video encoders produce 92.59% semantically dense representations" where individual time steps are nearly indistinguishable. Our VAE embeddings are pre-computed — we have no evidence that temporal density is lower.

### Hypothesis H2: Representation Density in VAE Embedding Space (HIGH CONFIDENCE)

The 1536-dim VAE embeddings (body + lhand + rhand) are computed from pose frame by frame. Adjacent frames in a signing sequence are often near-identical (slow hand movement between sign transitions). The mT5 encoder-decoder, processing this as `inputs_embeds`, sees a stream of nearly-identical vectors — making attention-based decoding degenerate.

Contrastive pre-training at the sequence level cannot fix this because it operates on pooled representations, not on the temporal structure.

### Hypothesis H3: val_m2t_loss / PPL Metric Artifacts (MEDIUM CONFIDENCE)

Final val_m2t_loss ~15-16, ppl ~1e8 — these numbers are implausibly large for a 80-epoch trained model on a 1077-sample val set. Either:
- The loss metric is computed incorrectly (teacher-forcing with label-shift bug?)
- The model's output distribution is extremely peaked/degenerate and BLEU collapses
- The validation loss averages across how2sign/phoenix (which are empty) and CSL, producing a distorted mean

Observation: `val_m2t_ppl 9.322e+07` vs `csl_BLEU_1 15.97` — the model can produce reasonable unigrams but perplexity is astronomically high. This is diagnostic of degenerate confidence calibration (output logits are extremely flat except for a few tokens).

### Hypothesis H4: LoRA Rank Too Low for Projection Learning (LOW CONFIDENCE)

LoRA rank=64, alpha=128 applied to the attention layers of mT5. The sign projection (1536→768) is also being fine-tuned but initialized from contrastive pre-training. If the LoRA doesn't have enough capacity to re-route the cross-attention to attend to sign-specific temporal patterns, the model defaults to language priors.

### Hypothesis H5: Data Scale (MEDIUM CONFIDENCE)

CSL-Daily train set: ~18k samples (but with 4 DDP ranks, effective batch is 18k / 4 / batch_size). At 80 epochs of 1150 steps each, the model sees ~18k×80=1.4M samples — but with high repetition. GFSLT-VLP methods use S3D trained on Kinetics-400 (large video pretraining) before SLT fine-tuning; our mT5 uses mt5-base which has no sign-language prior.

## What We Ruled Out

- **Embedding quality** (claim:C5): 1024-way CSL classifier at 81.8% top-1 confirms embeddings are discriminative. Problem is NOT zero information.
- **Pipeline correctness** (claim:C3): Overfit test shows the model CAN memorize, so the pipeline works.
- **Contrastive pre-training failure**: acc_s2t=27.7% (top-1/512) confirms alignment was learned. The projection IS useful for retrieval.
- **Corrupted data**: EOFError fixed; no samples are skipped in a way that would cause silent data loss.

## Proposed Next Steps (by priority)

1. **R015 — Representation Density Audit** (1 GPU, <1 hour)
   - Compute temporal cosine similarity of VAE embeddings within each CSL sample
   - Compare before/after contrastive pre-training
   - If density >80% (adjacent embeddings cosine_sim > 0.9), this is the primary cause

2. **B5-A — Temporal Contrastive (SignCL-style on VAE embeddings)** (1 GPU, 4h)
   - Apply SignCL margin loss to adjacent/distant frames within our VAE embedding sequences
   - Goal: reduce temporal density BEFORE feeding to mT5
   - If this works: M2 gate re-check

3. **B5-B — Debug val_m2t_loss metric** (diagnostic, <1h)
   - Print raw logits distribution during validation
   - Check if loss is computed correctly (label shift, padding mask, etc.)
   - Compare teacher-forcing train loss vs. inference loss

4. **B5-C — Pseudo-gloss alignment** (new direction)
   - Use Qwen/ChatGLM to generate pseudo-glosses from CSL-Daily Chinese annotations
   - Align VAE embeddings to pseudo-gloss positions
   - This would provide the intermediate compositional signal that Guo et al. 2025 show is critical

## Blocking Question

Before spending more GPU time, we need to know: **Is the bottleneck (a) temporal density, (b) val_m2t metric bug, or (c) data scale?** R015 (density audit, <1h) can answer (a); debugging val_m2t_loss code can answer (b).
